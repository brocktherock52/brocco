Claude Desktop MCP servers in 2026: 10 every builder should install

MCP went from "interesting protocol" to "the way Claude Desktop talks to your tools" in about six months. Here are the ten servers that justify the install time, what each one unlocks, and the configs to paste.

filesystemgithubbravepostgresbrocco slacknotionlinearstripetavily

If you opened Claude Desktop a year ago, it was a chat window. If you open it today, it's a chat window plus access to your filesystem, your codebase, your CRM, your database, your task tracker, your billing, and a dozen other things you didn't even know you wanted Claude to see. The thing that changed: Model Context Protocol (MCP), Anthropic's standard for letting Claude call tools that live outside the model.

The catch: there are now hundreds of MCP servers, most of them not worth installing. This post is a tested shortlist. Ten servers, what each one actually does for you, and the exact claude_desktop_config.json snippet to paste. By the end you'll have a Claude Desktop that can read your repo, query your database, draft a Linear ticket, post to Slack, and run multi-agent research jobs, all without leaving the conversation.

The 10

  1. Filesystem — read and write local files
  2. GitHub — issues, PRs, code search
  3. Brave Search — private web search
  4. Postgres — query your real database
  5. brocco — multi-agent runs as MCP tools
  6. Slack — read channels and post messages
  7. Notion — pages, databases, blocks
  8. Linear — issues, projects, cycles
  9. Stripe — customers, subscriptions, invoices
  10. Tavily — web search with synthesis

Quick MCP primer (skip if you've shipped one)

MCP is a JSON-RPC 2.0 protocol over stdin/stdout. A "server" is any process that registers a list of tools when Claude Desktop launches it. Claude calls a tool, the server runs whatever code it wants, returns a result. That's the entire shape.

You configure servers by editing claude_desktop_config.json (Claude Desktop » Settings » Developer » Edit Config). The file looks like:

{
  "mcpServers": {
    "name-of-your-choice": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-foo"],
      "env": { "API_KEY": "..." }
    }
  }
}

Restart Claude Desktop and the tools appear under the ↓ menu in the message input. You can call them in plain English: "use the filesystem tool to read package.json."

One operational note: Claude Desktop runs each server as a separate subprocess. Servers that need network or credentials get them through the env block in the config. Don't put real secrets in a file you commit. Use a .env.local file the config references, or a secret manager.

1. Filesystem MCP server

This is the one to install first. The official @modelcontextprotocol/server-filesystem gives Claude Desktop read and write access to a directory you scope. Claude can read your project, edit files, run git, all without you copy-pasting code into the chat.

"filesystem": {
  "command": "npx",
  "args": [
    "-y",
    "@modelcontextprotocol/server-filesystem",
    "/Users/you/projects/my-app",
    "/Users/you/Documents"
  ]
}

Pass one or more directory paths as args. Claude can read, write, and list anything inside those roots, but cannot escape them. If you only want read-only access, scope to a directory the user-account doesn't have write permission on.

What this unlocks: "read README.md, then update package.json to bump the version, then write a CHANGELOG entry."

2. GitHub MCP server

The official GitHub MCP server lets Claude search repos, read issues and PRs, write comments, and create issues or PRs. Faster than asking Claude to invent code that might not match what's actually on main.

"github": {
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": {
    "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_..."
  }
}

Generate a token at github.com/settings/tokens with repo + read:org scopes. The server respects the token's permissions, so you can use a fine-grained token scoped to one repo if you want.

What this unlocks: "search issues in brocco-ai/charter for 'BOM' and summarize the resolved ones."

3. Brave Search MCP server

Web search inside Claude Desktop without paying Anthropic for the search-augmented model tier. Brave's API is cheap (free tier 2k queries/mo, $5/mo for 20k) and the privacy story is actually believable.

"brave": {
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-brave-search"],
  "env": { "BRAVE_API_KEY": "..." }
}

Why Brave specifically: their API doesn't track queries, doesn't bias toward Bing's index, and works without a card on the free tier. If you want Tavily-style synthesis instead of raw search results, see #10 below.

4. Postgres MCP server

Read-only query access to a Postgres database from inside the chat. The official @modelcontextprotocol/server-postgres defaults to read-only, which is the right default for Claude. Schema introspection on connect, so Claude knows your tables.

"postgres": {
  "command": "npx",
  "args": [
    "-y",
    "@modelcontextprotocol/server-postgres",
    "postgresql://user:pass@host:5432/mydb"
  ]
}

What this unlocks: "how many users signed up last week, broken down by referral source?" Claude writes the SQL, runs it, summarizes. Three steps you used to do by tabbing to Metabase.

For writes, run a separate server with a different name and a write-permission database role. Don't use the same role for both.

5. brocco (multi-agent runs as MCP tools)

This is where this list stops being just a tool aggregator and starts being a multi-agent platform. brocco is a multi-agent dashboard where each agent (researcher, coder, outreach, supervisor, planner, browser, designer, app_builder, analyst) has its own system prompt and tool set. The brocco MCP server exposes every agent as one MCP tool.

So instead of "search the web for X, then fetch URL Y, then synthesize a brief", you say "use brocco_researcher to give me a brief on X", and brocco runs the full agent loop end-to-end inside Claude Desktop. The output comes back as a single tool result with a sourced markdown brief.

"brocco": {
  "command": "python",
  "args": ["-m", "charter.mcp_server"],
  "env": {
    "ANTHROPIC_API_KEY": "sk-ant-...",
    "TAVILY_API_KEY": "tvly-..."
  }
}

Install: git clone https://github.com/brocco-ai/charter && pip install -e . in that directory once. Setup writeup at brocco.ai/download.

Why combine MCP servers this way: each brocco agent already knows the right tool sequence for its specialty. The researcher agent knows to search-then-fetch-then-synthesize. The coder knows to read-then-plan-then-write. By exposing them as MCP tools, you skip the prompt engineering Claude would otherwise need to choreograph the same multi-step loop.

6. Slack MCP server

The official Slack MCP server lets Claude read channel history and post messages. Combined with the brocco researcher, this becomes "summarize this week's #engineering channel and post the summary to #weekly-updates."

"slack": {
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-slack"],
  "env": {
    "SLACK_BOT_TOKEN": "xoxb-...",
    "SLACK_TEAM_ID": "T0123ABCD"
  }
}

Generate the bot token at api.slack.com/apps. Required scopes: channels:history, chat:write, users:read. Add the bot to channels you want it to access.

7. Notion MCP server

Read pages, write blocks, query databases. The official Notion server respects your integration's page-level permissions, so it can only see what you've shared with it.

"notion": {
  "command": "npx",
  "args": ["-y", "@notionhq/notion-mcp-server"],
  "env": { "NOTION_API_KEY": "secret_..." }
}

What this unlocks: "draft a one-pager based on the 'Q3 Goals' page in Notion, save it as a new sub-page."

8. Linear MCP server

Issue creation, status updates, project queries. Less mature than the GitHub or Slack servers, but the killer use case is "create three Linear issues for the bugs we just discussed, assign them to me, put them in the next cycle."

"linear": {
  "command": "npx",
  "args": ["-y", "linear-mcp-server"],
  "env": { "LINEAR_API_KEY": "lin_api_..." }
}

Generate the key at linear.app/settings/api. Read-only is enough for most workflows; only switch to write scope when you trust your prompts.

9. Stripe MCP server

Customer lookup, subscription queries, invoice creation. Stripe's official MCP server is read-write, so be cautious about prompts that could move money. Default to a restricted API key.

"stripe": {
  "command": "npx",
  "args": ["-y", "@stripe/mcp"],
  "env": { "STRIPE_API_KEY": "rk_live_..." }
}

What this unlocks: "how many active subscribers do we have on the Solo plan, what's MRR, who churned this week?" Three queries you used to do by clicking around the Stripe dashboard.

10. Tavily MCP server

Web search with built-in synthesis. Brave (#3) returns raw results; Tavily returns "the answer is X, here are the 5 best sources." Different use cases. Use Tavily when you want a quick answer, Brave when you want sources to skim.

"tavily": {
  "command": "npx",
  "args": ["-y", "tavily-mcp"],
  "env": { "TAVILY_API_KEY": "tvly-..." }
}

Tavily's free tier is 1k searches/mo, paid starts at $20/mo for 4k. Worth it if you do real research-heavy work in Claude Desktop.

How to combine them (the part most posts skip)

The interesting prompts are the ones that chain three or four of these:

"Use brocco_researcher to find the top 3 customer-support competitors, then query the Postgres MCP to pull our last 30 days of NPS, then create a Linear issue summarizing the gap and assign it to @sarah."

Claude figures out the order by reading each tool's description. The trick is naming your servers clearly. "brocco_researcher" is more discoverable to Claude than "server-1". Likewise "postgres-prod" vs "postgres-staging" if you have multiple environments.

Two combinations that earn their keep weekly for me:

  • brocco + Slack + Notion: Monday morning, "use brocco_planner to turn last week's Slack #wins channel into a 5-bullet weekly review, save it to the Notion 'Weekly Reviews' database." Done in 90 seconds.
  • GitHub + filesystem + brocco_coder: "read the latest issue in brocco-ai/charter, then read the relevant file via filesystem, then use brocco_coder to draft the fix as a diff."

Servers I deliberately left off

Browser-automation MCP servers (Playwright, browser-use) are powerful but slow and finicky. Better to use a managed service via REST. Calendar MCP servers exist but Google Calendar's MCP is rough; use the browser. Email MCPs are dangerous (silent send), avoid until they sandbox better. Twitter MCPs are mostly dead since the API priced out indie use.

What's coming

The MCP surface is going to keep expanding for at least another year. Watch for: HTTP transport (so MCP servers can be deployed anywhere, not just stdio), better permission UX (per-tool approval inside Claude), and more first-party servers from CRM and accounting vendors. By Q4 2026 the question won't be "what MCP server should I install" but "which 50 are turned on right now and how do I keep track of which one Claude is calling."

For now: install the ten above, restart Claude Desktop, watch the tools menu fill up. Most of your normal work happens at that menu now.
